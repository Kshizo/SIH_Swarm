Bringup

From clone to flying

Needs ROS 2 Jazzy, Gazebo Harmonic, a built ArduPilot SITL, ardupilot_gazebo, MicroXRCEAgent, and ardupilot_msgs on the prefix path.

1

Fetch the odometry package the repo left empty

src/rf2o_laser_odometry is committed as a bare directory — it was a submodule once.

$ cd swarm_ws/src && git clone -b ros2 \
    https://github.com/MAPIRlab/rf2o_laser_odometry.git
2

Install the detector runtime

person_detector imports ai_edge_litert. Install it into your user site, then make sure NumPy stays on 1.x — the system OpenCV and cv_bridge are built against it and will not import under NumPy 2. 

$ pip install --user --break-system-packages ai_edge_litert
$ pip uninstall -y --break-system-packages numpy   # keep the distro 1.26
3

Build the workspace

Delete the committed build/ and install/ first — their CMake caches point at another machine.

$ cd swarm_ws && rm -rf build install log
$ source /opt/ros/jazzy/setup.bash && source ~/ardu_ws/install/setup.bash
$ colcon build --symlink-install
4

Generate the simulation assets

The drone model is spliced onto ardupilot_gazebo's iris_with_ardupilot at generation time rather than vendored, so nothing LGPL is committed here. The world writes itself from the maze data. 

$ python3 sim/tools/gen_drone_models.py
$ python3 sim/tools/gen_world.py
5

Fly it

Starts Gazebo, both autopilots, both XRCE agents and both ROS stacks, logs each to sim/logs/<timestamp>/, and tears the whole tree down on Ctrl-C. 

$ ./sim/run_swarm.sh                 # both drones, GUI
$ ./sim/run_swarm.sh --drones 1 --headless
6

Watch it work

Map, laser scan, the planned path and the survivor pins all render in RViz.

$ ROS_DOMAIN_ID=1 rviz2      # /map, /scan, /person_map_pins
$ mavproxy.py --master=udpin:127.0.0.1:14551

Ledger

What was broken, and what still bites

Each of these stopped the stack cold somewhere between git clone and takeoff.

Fixed

Simulation assets absent

The launch files bridge /drone1/lidar/scan and reference a maze_survivors world that exists nowhere in the repo. Both drone models and the world are now generated under sim/.

Fixed

Depth never reached the detector

The bridge remapped RGB and lidar but not depth, so person_detector waited forever on /camera/depth_image and its time synchroniser never fired.

Fixed

GPS-denied params renamed upstream

ArduPilot 4.6 moved GPS_TYPE to GPS1_TYPE. The old names were silently ignored, the simulated GPS stayed on, and arming failed with “GPS and AHRS differ by 13.6 m”.

Fixed

EKF source sets 2 and 3

The pre-arm check walks every source set, not just the active one. Sets 2 and 3 still defaulted to GPS, so arming failed with “EK3 sources require GPS” even with set 1 on external nav.

Fixed

Coverage layer had no input

frontier_exploration read a scan_raw topic nothing published, and re-published onto /scan, which the bridge already owned. It now reads the bridged scan and publishes its gated copy to /scan_gated.

Watch

NumPy 2 breaks cv_bridge

Anything that pulls NumPy 2 into your user site — installing the detector runtime does — takes OpenCV and cv_bridge down with it. Keep the distro's 1.26.
